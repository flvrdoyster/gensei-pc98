# 환세쾌도전 역공학 노트

**대상 게임**: 환세쾌도전 / 幻世快盗伝 (Compile Inc., 1995, PC-98)  
**상태**: 텍스트 추출 완료 (v6 파서, 구조화된 추출)  
**역공학 방법**: GSC.COM 디스어셈블 (capstone) + DISK_B.DAT LZ 압축 해제 후 정적 분석

---

## 파일 구성

```
original/kaitou/

  DISK_B.DAT  334,744 B   스크립트 인터프리터 + 텍스트 + 그래픽 + 음악
  DISK_C.DAT  562,637 B   그래픽 데이터 (텍스트 없음)
  PLAY1~8.INF   3,193 B   스테이지 맵 데이터 (텍스트 없음)
  BPLAY/FPLAY.COM         FM/SSG 음악 재생기
```

**텍스트 소스**: DISK_B.DAT 단일 파일. DISK_C.DAT·PLAY*.INF에는 번역 대상 없음.

## 핵심 발견: LZ 압축

**DISK_B.DAT는 LZ 압축** — 풍광전과 동일한 알고리즘.

```python
# compile_lz.decompress() 그대로 재사용 가능
dec = decompress(data, seek_pos)
```

GSC.COM 내 디스어셈블 확인 (0xf55):
- back-ref: `length = (al & 0x7f) + 3`, `offset = next_byte + 1`  
- literal: `length = al` (al < 0x80)
- 종료: `al == 0`

→ `compile_lz.py`의 `decompress()` 함수 동일 알고리즘, 그대로 적용.

## DISK_B.DAT 청크 테이블

```
파일 오프셋 0x000~0x3FF: 4-byte 엔트리 테이블
  [CX(2 LE), DX(2 LE)] → seek_pos = (CX<<16)|DX

엔트리 수: 65개
seek_pos=0 엔트리는 무시 (빈 슬롯)
```

코드 예시:
```python
seeks = []
for off in range(0, 0x400, 4):
    cx = struct.unpack_from('<H', data, off)[0]
    dx = struct.unpack_from('<H', data, off + 2)[0]
    seek = (cx << 16) | dx
    if seek and seek < len(data):
        seeks.append(seek)
seeks.sort()
# 압축 크기 = seeks[i+1] - seeks[i]
```

> ⚠️ 이전 NOTES에서 "8-byte 엔트리, type=0000 청크" 로 기록한 것은 **오류**. 실제로는 4-byte 엔트리.

## 스크립트 제어코드 (확정)

### 62 00: 직접 텍스트 블록 (스킬/아이템 설명)

```
62 00 XX XX   블록 시작 (2바이트 인수)
[SJIS]        스킬/아이템 이름 (직접 배치)
64 XX         서브 레이블 시작 (소비 MP/SP 등)
[SJIS]        서브 레이블 텍스트
72 XX         줄바꿈
[SJIS]        설명 줄 (여러 줄 가능)
65            블록 종료
```

예시 (청크 3):
```
62 00 0f 03  脳天砕
64 0c        消費ＳＰ１０
72 01        こん身の力を込め　剣を
72 01        敵の脳天めがけて振り下ろす
65
```

청크 3 앞부분은 2-byte LE jump table (index → 블록 offset). 0x88 = 빈 슬롯 포인터.

### 6e 00 67: 화자 포함 대화 블록

```
6e 00   대화 섹션 시작
67 XX   화자 마커 (XX = 화자 ID)
[SJIS]  화자명  ※ 「로 시작하면 화자 없는 첫 대사
72 XX   줄바꿈
[SJIS]  대화 텍스트
72 XX   줄바꿈 (대화 줄 구분)
73 XX   대화 블록 종료
```

예시:
```
6e 00  67 01  アリババ
72 01  「誰だ？
72 01  　入っていいぞ
73 30
```

### 6b 00: 화자 없는 대화 블록

```
6b 00 80 77 00   텍스트 블록 시작 (5바이트 헤더)
[SJIS]           대화 텍스트
72 XX            줄바꿈
73 XX            블록 종료

6b 00 81 65      빈 슬롯 (4바이트)
```

청크 31 앞부분에서 6e 00 67 이전에 집중 출현. 화자명 없이 NPC 대사 직접 배치.

예시:
```
6b 00 80 77 00  「おや　旅の人かい
72 01           なにもないとこだけど
73 30
```

### 6d 08: 적/아이템 이름 블록

```
6d 08   이름 블록 시작
[SJIS]  이름 (SJIS 쌍만, 32바이트 이하)
65      블록 종료
```

청크 61-64에서 적/캐릭터 이름. 엄격 모드 파싱 (SJIS만 허용, 혼합 블록 자동 제외).

### 64 XX: 이름/레이블 블록 (XX ≠ 00)

```
64 XX   레이블 시작
[SJIS]  이름 또는 레이블 텍스트
65      블록 종료
```

확인된 XX 값:
- `64 f6`: 캐릭터/적 이름 (`アリババ`, `スマッシュ` 등)
- `64 fc`, `64 01`: 상태 효과 (`毒`, `気絶`)
- `64 ff`, `64 fe`: UI 기호

### 64 00 / 64 0a / 64 0c: 챕터 제목 / 스탯 라벨

```
64 00 XX XX   챕터 제목 시작 (2바이트 인수)
[SJIS]        제목 텍스트

64 0a         스탯 라벨 (素早さ 등 — 인수 없음)
[SJIS]        라벨 텍스트

64 0c         스탯 라벨 (運 등 — 인수 없음)
[SJIS]        라벨 텍스트
```

### 72 01 [가이지]: UI 컬럼 헤더

```
72 01 85 XX [85 XX ...]   가이지 문자열 렌더 명령
```

청크 0에서만 관찰됨. H・P, S・P, M・P, EXP 등 전투/스탯 화면 컬럼 헤더.  
각 `72 01` 시퀀스가 하나의 독립 라벨. 번역 가능 (가이지→SJIS 교체 방식).

### 72 02 [SJIS]: 스탯 이름

```
72 02 [SJIS]   스탯 이름 렌더 명령
```

청크 0 스탯 화면에서 관찰. 生命力, 攻撃力, 防御力 등.  
다음 제어코드(64 XX, 65 등)에서 종료.

### 기타 확인된 제어코드

| 바이트 | 역할 | 인수 |
|--------|------|------|
| `65`    | 블록 종료 | 없음 |
| `67 XX` | 화자 마커 | 1바이트 |
| `72 XX` | 줄바꿈 / 렌더 명령 | 1바이트 |
| `73 XX` | 대화 블록 종료 | 1바이트 |
| `76 1a` | 미확정 (단독 메시지 앞에 출현) | 1바이트 추정 |

## 파서 구조 (`kaitou_parser.py` v5)

### 알고리즘

1. **청크 테이블 파싱** → 65개 청크의 (seek, comp_size) 추출
2. **각 청크 LZ 해제** → `compile_lz.decompress(data, seek)`
3. **SJIS 밀도 계산** → 5% 미만 + 명시적 노이즈 청크(`NOISE_CHUNKS`) 스킵
4. **구조화 파서를 순서대로 실행** (각 파서는 소비 바이트를 `consumed` 셋에 기록):
   - `extract_dialogue_blocks()` — `6e 00 67` 앵커
   - `extract_6b_dialogue_blocks()` — `6b 00 80 77 00` 앵커
   - `extract_simple_blocks()` — `62 00 XX XX` 직접 텍스트 블록
   - `extract_72_labels()` — `72 01 [가이지]` / `72 02 [SJIS]` UI 라벨 (**name보다 먼저 — consumed 충돌 방지**)
   - `extract_name_blocks()` — `64 XX` 앵커 (XX≠00)
   - `extract_6d_name_blocks()` — `6d 08` 앵커 (적/아이템 이름)
   - `extract_title_labels()` — `64 00/0a/0c` 앵커 (챕터 제목 + 스탯 라벨)
5. **SJIS 런 폴백** — `find_block_ranges()`로 `62 00` 블록 내부만 eligible, `consumed` 제외
6. **중복 제거**: 동일 (chunk, offset) 쌍 제거

### 노이즈 처리 방침

- **명시적 노이즈 청크** (`NOISE_CHUNKS = {8, 9, 37, 42, 44, 48, 58, 59}`): 완전 스킵
- **`62 00` 블록 경계 제한**: SJIS 런 폴백은 `62 00 XX XX ... 65` 블록 내부로만 제한
  - 첫 콘텐츠 바이트 쌍이 유효 SJIS 쌍이어야 텍스트 블록으로 인정
  - x86 코드 영역(청크 0 등)의 거짓 양성 제거
- **`6d 08` 엄격 모드**: SJIS 쌍만 허용, 32바이트 상한 → 혼합 블록 자동 제외
- **임계값 필터 없음**: 분류는 번역자가 에디터에서 직접

### 추출 결과 (v5, 노이즈 청크 제외)

| 파서 | 대상 패턴 | 주요 청크 |
|------|----------|---------|
| dialogue | `6e 00 67` | 2, 6, 11, 13, 15, 19, 22, 23, 29~34, 41 |
| 6b dialogue | `6b 00 80 77 00` | 31 |

### Phase 2: 인서터 (`kaitou_inserter.py`)

압축이 없으면 단순 직접 패치인 풍광전과 달리, 쾌도전은 LZ 재압축 필요:

| 항목 | 풍광전 | 쾌도전 |
|------|--------|--------|
| 파일 포맷 | CMD (LZ 압축) | DAT (청크별 LZ 압축) |
| 재압축 | 필요 | 필요 |
| 길이 제약 | jp_len 바이트 | jp_len 바이트 (동일 추정) |

핵심 과제: 패치된 청크를 LZ 재압축 → DISK_B.DAT에 쓰기.  
청크 크기 변하면 이후 청크들의 seek_pos 재계산 필요.

#### ⚠️ 인서터 예외: 청크 0 스킬명+SP코스트 블록

청크 0의 스킬 데이터 구간(오프셋 ~39924~)에서 스킬명과 SP 코스트가 구분자 없이 직결된다:

```
62 00 0c 01
[스킬명 SJIS][SP코스트 가이지(0x85XX)]
62 00 05 01 65   ← 빈 설명 블록
```

예시: `脳天砕` (SJIS 6바이트) + `(SP10)` (가이지 12바이트) → translation.json에 `脳天砕(SP10)`으로 통합 저장.

**인서터 처리 방침**:
- 번역 대상은 앞쪽 SJIS 스킬명만 (한글로 교체)
- 뒤쪽 `0x85XX` 가이지 바이트(SP 코스트)는 **그대로 보존**
- 교체 시 원본 jp에서 첫 `0x85` 등장 위치를 경계로 삼아 앞부분만 덮어쓸 것
- `jp_len`은 이름+코스트 합산이므로 실제 이름 바이트 수는 직접 계산해야 함

청크 3의 동일 스킬은 `64 XX`로 이름/코스트/설명이 분리돼 있어 처리 방식이 다름에 주의.
