# 환세쾌도전 역공학 노트

**대상**: 환세쾌도전 / 幻世快盗伝 (Compile Inc., 1995, PC-98)  
**상태**: 번역 진행 중, 인서터 미구현  
**도구**: `kaitou_parser.py` (추출)

---

## 개요

### 파일 구성

```
original/kaitou/
  GSC.COM       3,936 B   로더 (DISK_*.DAT 로드 + LZ 해제)
  DISK_B.DAT  334,744 B   스크립트·텍스트·그래픽·음악 (65개 청크)
  DISK_C.DAT  562,637 B   그래픽 데이터 (텍스트 없음)
  PLAY1~8.INF   3,193 B   스테이지 맵 데이터 (텍스트 없음)
```

**텍스트 소스**: DISK_B.DAT 단일 파일.

### DISK_B.DAT 청크 구조

```
0x000~0x3FF: 4-byte 엔트리 테이블
  [CX(2 LE)][DX(2 LE)] → seek_pos = (CX<<16)|DX
총 65개 청크. seek_pos=0 엔트리는 빈 슬롯.
압축 크기 = seeks[i+1] - seeks[i]
```

### 청크 목록 (텍스트 관련)

| 청크 | 해제크기 | 내용 |
|------|---------|------|
| 0 | 56,734 B | x86 인터프리터 코드 + UI 임베드 문자열 |
| 1 | 3,691 B | 인트로 컷씬 + 메뉴 |

| 6 | 30,207 B | 챕터 제목 + 대화 |

| 8,9,37,42,44,48,58,59 | — | 노이즈 (그래픽/비트맵, `NOISE_CHUNKS` 제외) |

## 작업 흐름

### 1. 압축 해제

LZ 알고리즘은 풍광전과 동일 — `compile_lz.decompress()` 재사용. 알고리즘 상세는 `NOTES_hukyou.md` 참조.

쾌도전 고유 구조 — DISK_B.DAT 청크 테이블 파싱:
```python
seeks = []
for off in range(0, 0x400, 4):
    cx = struct.unpack_from('<H', data, off)[0]
    dx = struct.unpack_from('<H', data, off + 2)[0]
    seek = (cx << 16) | dx
    if seek and seek < len(data):
        seeks.append(seek)
seeks.sort()
```

### 2. 제어코드

| 바이트 | 역할 | 인수 |
|--------|------|------|
| `62 00 XX XX` | 블록 시작 (직접 텍스트 또는 대화 컨테이너) | 2바이트 |
| `64 00 XX XX` | 챕터 제목 시작 | 2바이트 |
| `64 0a` | 스탯 라벨 (素早さ 등) | 없음 |
| `64 0c` | 스탯 라벨 (運 등) | 없음 |
| `64 XX` (기타) | 이름/레이블 블록 (XX=f6·fc·01 등) | 없음 |
| `65` | 블록 종료 | 없음 |
| `67 XX` | 화자 마커 | 1바이트 |
| `6b 00 80 77 00` | 화자 없는 대화 블록 | |
| `6b 00 81 65` | 빈 대화 슬롯 | |
| `6d 08` | 적/아이템 이름 블록 | |
| `6e 00 67` | 화자 포함 대화 블록 앵커 | |
| `72 01 [85XX…]` | UI 컬럼 헤더 (가이지 문자열) | |
| `72 02 [SJIS]` | 스탯 이름 (生命力·攻撃力 등) | |
| `72 XX` | 줄바꿈 | 1바이트 |
| `73 XX` | 대화 블록 종료 | 1바이트 |

`62 00` 블록 예시 (청크 3 스킬):
```
62 00 0f 03
脳天砕            ← 스킬명 SJIS
64 0c  消費ＳＰ１０
72 01  こん身の力を…
72 01  敵の脳天めがけ…
65
```

### 3. 가이지 (0x85XX)

풍광전과 동일 체계. `compile_lz.read_sjis_char()` / `encode_gaiji_char()` 재사용.

쾌도전 특이점: `72 01 85XX [85XX…]` 패턴으로 UI 컬럼 헤더(H・P, S・P, M・P, EXP 등)에 사용.  
인서터 구현 시 가이지→SJIS 교체 가능 (풍광전과 동일 방식).

### 4. 파싱

`kaitou_parser.py` 실행 → `translation/kaitou/translation.json` 생성.

추출기 실행 순서 (순서 중요 — `consumed` 셋으로 바이트 중복 방지):
1. `extract_dialogue_blocks` — `6e 00 67` 앵커
2. `extract_6b_dialogue_blocks` — `6b 00 80 77 00` 앵커
3. `extract_simple_blocks` — `62 00 XX XX` 직접 텍스트
4. `extract_72_labels` — `72 01 [가이지]` / `72 02 [SJIS]` UI 라벨 (**name보다 먼저**)
5. `extract_name_blocks` — `64 XX` 앵커
6. `extract_6d_name_blocks` — `6d 08` 앵커
7. `extract_title_labels` — `64 00/0a/0c` 앵커
8. `extract_sjis_runs` — `62 00` 블록 내부 잔류 SJIS (폴백)

`translation.json` 최상위 키: `entries`.  
각 엔트리 필드: `file`, `chunk`, `offset`, `type`, `jp`, `kr`, `lines`.  
`lines`는 엔트리 내 개별 줄 — 각각 `offset`, `jp`, `jp_len`, `kr`, `tag`.

### 5. 인서트

**미구현.** 설계 방침:
- 패치된 청크를 LZ 재압축 (풍광전과 동일 알고리즘)
- DISK_B.DAT 재조립: 청크 크기 변경 시 이후 모든 청크의 seek_pos 재계산 필요
- 청크 0 스킬명+SP코스트 직결 구조 예외 처리 (아래 참고)

## 참고

**청크 0 노이즈**: x86 인터프리터 코드가 혼재 → `0xe0~0xef` 표준 SJIS 범위로 제한 (`is_sjis_pair`), `NOISE_CHUNKS` 별도 관리. `64 0a`/`64 0c` 오인식 방지를 위해 첫 콘텐츠 바이트가 SJIS 선행 바이트인지 확인.

**청크 0 스킬명+SP코스트 직결**: 스킬명 SJIS + SP코스트 가이지(`0x85XX`)가 구분자 없이 붙어 있음.
```
62 00 0c 01
[스킬명 SJIS][SP코스트 0x85XX…]
```
인서터에서 첫 `0x85` 등장 위치를 경계로 앞부분만 교체, 뒤쪽 가이지 바이트 보존.  
청크 3의 동일 스킬은 `64 XX`로 분리돼 있어 처리 방식 다름.

**`6d 08` 엄격 모드**: SJIS 쌍만 허용, 32바이트 상한 — 혼합 블록 자동 제외.
