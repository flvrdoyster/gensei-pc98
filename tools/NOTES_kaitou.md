# 환세쾌도전 역공학 노트

**대상 게임**: 환세쾌도전 / 幻世快盗伝 (Compile Inc., 1995, PC-98)  
**상태**: 텍스트 추출 진행 중 (v2 파서 완료, 제어코드 미확정)  
**역공학 방법**: 정적 분석 (capstone 디스어셈블) + 추후 DOSBox-X 런타임 분석

---

## 파일 구성

```
original/kaitou/
  GSC.COM       3,936 B   게임 로더 (DISK_*.DAT + PLAY*.INF 로드)
  DISK_B.DAT  334,744 B   스크립트 인터프리터 + 텍스트 + 그래픽 + 음악
  DISK_C.DAT  562,637 B   그래픽 데이터 (텍스트 없음)
  PLAY1~8.INF   3,193 B   스테이지 맵 데이터 (텍스트 없음)
  BPLAY/FPLAY.COM         FM/SSG 음악 재생기
```

**텍스트 소스**: DISK_B.DAT 단일 파일. DISK_C.DAT·PLAY*.INF에는 번역 대상 없음.

---

## DISK_B.DAT 구조

```
DISK_B.DAT (334,744 bytes)
├── 0x000~0x107  청크 인덱스 (33개 × 8바이트)
│                  엔트리: [hi_type(1), lo_type(1), offset_LE(4), field(2)]
│                  offset=0 && type=0000 → 인덱스 종료 마커
├── 0x000400~    type=0000  스크립트/텍스트  4개  ~92 KB  ← 번역 대상
├── 0x0148b6~    type=0100  그래픽           4개
├── 0x0214e5~    type=0200  음악             4개
├── 0x030bad~    type=0300  미확인           5개
├── 0x040410~    type=0400  미확인          14개
└── 0x0504ea~    type=0500  미확인           2개
```

### type=0000 청크 상세

| 청크 | 시작 | 끝 | 크기 | 주요 내용 |
|------|------|-----|------|----------|
| 0 | 0x000400 | 0x008172 | 32 KB | 인터프리터 코드 + UI/전투 메뉴 + 인트로 |
| 1 | 0x008172 | 0x00d635 | 22 KB | 메인 스토리 대화 (챕터 1~3) |
| 2 | 0x00d635 | 0x0148b6 | 29 KB | 메인 스토리 대화 (챕터 4~8) |
| 3 | 0x01f21b | 0x0214e5 |  9 KB | 후반부 대화 + 엔딩 |

**주의**: 각 청크에는 x86 인터프리터 코드와 스크립트 데이터가 혼재.  
코드 영역의 바이트가 우연히 SJIS로 디코딩되는 오탐(false positive) 발생.

## 스크립트 제어코드

### 확인된 것

| 바이트 | 역할 | 근거 |
|--------|------|------|
| `62 00 XX XX` | 대화 블록 헤더 (4바이트) | 텍스트 직전에 반복 출현, 블록 경계 일치 |
| `72 XX` | 줄바꿈 (line break) | 풍광전과 동일, 텍스트 흐름 검증 |

### 추정 (미확정)

| 바이트 | 추정 역할 |
|--------|----------|
| `65 XX` | 페이지 전환 또는 입력 대기 |
| `64 XX` | 탭/열 제어 (스탯창 정렬) |
| `6b XX` | 블록 종료? |
| `ff ff` | 청크 종료 마커? |

### 디스패처 (정적 분석)

DISK_B.DAT 파일 오프셋 0x32f1:

```asm
mov  bl, al           ; 제어코드 → BX
xor  bh, bh
shl  bx, 1
jmp  word ptr [bx + 0x7e5d]  ; 점프 테이블
```

- 점프 테이블 주소 `0x7e5d`는 메모리 주소 (파일 오프셋 아님)
- 로드 세그먼트를 모르므로 정적으로 핸들러 코드를 직접 분석 불가
- **DOSBox-X 런타임 분석으로 확정 필요**

## 현재 파서 전략 (`kaitou_parser.py` v2)

풍광전처럼 제어코드를 완전히 파악하기 전에 쓸 수 있는 "밀도 기반" 근사 파서.

### 알고리즘

1. **청크 인덱스 동적 파싱** → type=0000 범위 4개 추출
2. **고밀도 영역 탐지**: 256바이트 윈도우를 64바이트 스텝으로 슬라이딩,  
   SJIS 비율 ≥ 0.30인 구간 → 스크립트 영역으로 분류
3. **라인 단위 추출**: 스크립트 영역에서 `72 XX`를 줄바꿈으로 인식, 라인별 수집
4. **런 그룹 보완**: 전체 type=0000 청크에서 gap ≤ 16바이트인 SJIS 런을 그룹화  
   → 고밀도 탐지가 놓친 메뉴·UI 보완
5. **중복 제거 후 통합**: 텍스트 기준 dedup, 오프셋 순 정렬

### 출력 현황 (v2)

| 타입 | 수 | 내용 |
|------|-----|------|
| `unknown` | 515 | 런 그룹 (일부 노이즈 포함) |
| `line_unknown` | 85 | 72 XX 줄바꿈 대화 라인 |
| `item` | 26 | 아이템/스킬 설명 |
| `dialog` | 6 | 62 00 블록 직후 텍스트 |
| `menu` | 3 | 메인·저장·전투 메뉴 |
| `line_item` | 6 | 기타 |
| **합계** | **641** | |

확인된 핵심 텍스트: 메인 메뉴 (`最初から遊ぶ` 등), 전투 메뉴 (`攻　撃`/`魔　法`/`特　技`…),  
상태창 레이블 (`レベル`/`生命力`…), 스킬 설명, 인트로·각 챕터 대화

### 한계

- 코드 영역 false positive: 기계어 바이트가 우연히 SJIS로 디코딩되는 ~100개 garbage 엔트리
- 제어코드 인수 길이 미확정 → 텍스트 중간에 제어코드 바이트가 혼입되는 현상
- 같은 대화가 `dialog` + `line_unknown` 양쪽에 중복 수집되는 경우 존재

## 다음 단계 — 접근 방향

### Phase 1: 런타임 제어코드 분석 (DOSBox-X)

목표: 제어코드 인수 바이트 수 확정 → 파서를 풍광전 수준의 상태 머신으로 업그레이드

```bash
dosbox-x -conf tools/dosbox-kaitou.conf
# Alt+Pause → 디버거 오픈
```

확인 항목:
1. **로드 세그먼트**: INT 21h AH=48h 반환값 (ES) — DISK_B.DAT가 어느 세그먼트에 로드되는지
2. **62 00 핸들러**: `BP <handler_addr>` → DS:SI로 스크립트 스트림 포인터 확인
3. **각 opcode 핸들러**: `si` 증가량 = 인수 바이트 수

우선 확인할 핸들러:
- `0x62` (대화 블록) → 4바이트 헤더 확인
- `0x72` (줄바꿈) → 1바이트 인수 확인
- `0x65`, `0x64`, `0x6b` → 인수 바이트 수

### Phase 2: 파서 v3 — 상태 머신 파서

런타임 분석으로 제어코드 인수 길이 확정 후 구현.

```python
# 목표 구조
def parse_script(data, start, end):
    # 풍광전 hukyou_parser.py와 유사한 상태 머신
    # IN_BLOCK / OUT_OF_BLOCK
    # 각 opcode마다 인수 바이트 정확히 소비
    # 노이즈 없는 클린한 텍스트 추출
```

예상 출력: 현재 641개 → 200~300개 (노이즈 제거, 구조화)

### Phase 3: `kaitou_inserter.py`

풍광전 `hukyou_inserter.py`를 참고하되 구조 차이 반영:

| 항목 | 풍광전 | 쾌도전 |
|------|--------|--------|
| 파일 포맷 | CMD (LZ 압축) | DAT (청크, 비압축) |
| 텍스트 위치 | 압축 해제 후 오프셋 | 파일 직접 오프셋 |
| 재압축 | LZ 재압축 필요 | 불필요 (직접 패치) |
| 길이 제약 | jp_len 바이트 | 미확정 (런타임 분석 필요) |

핵심 차이: 압축이 없으므로 삽입이 단순. 단 인터프리터가 고정 오프셋 참조를 쓴다면  
길이 변경 불가 → **번역 텍스트를 원문과 동일 바이트 수로 맞춰야 함** (가능성 높음).

### Phase 4: 한글 폰트 패치

쾌도전의 폰트 저장 방식 분석 필요:
- 풍광전: `GAIJI.DAT` (외자 비트맵)
- 쾌도전: DISK_B.DAT 내 폰트 데이터 추정 (type=0300~0400 청크)

확인 방법: DOSBox-X에서 폰트 렌더링 코드(VRAM 쓰기 직전)에 브레이크포인트

### Phase 5: 번역 + 재삽입 테스트

1. `translation/kaitou/translation.json`의 `kr` 필드 채우기 (Phase 2 완료 후)
2. `kaitou_inserter.py` 실행 → `build/kaitou/DISK_B.DAT` 생성
3. DOSBox-X에서 패치된 파일로 게임 실행 → 한글 표시 확인
