# 환세쾌도전 역공학 노트

**대상 게임**: 환세쾌도전 / 幻世快盗伝 (Compile Inc., 1995, PC-98)  
**상태**: 텍스트 추출 완료 (v3 파서, 구조화된 추출)  
**역공학 방법**: GSC.COM 디스어셈블 (capstone) + DISK_B.DAT LZ 압축 해제 후 정적 분석

## 파일 구성

```
original/kaitou/
  GSC.COM       3,936 B   게임 로더 (DISK_*.DAT + PLAY*.INF 로드 + LZ 해제)
  DISK_B.DAT  334,744 B   스크립트 인터프리터 + 텍스트 + 그래픽 + 음악
  DISK_C.DAT  562,637 B   그래픽 데이터 (텍스트 없음)
  PLAY1~8.INF   3,193 B   스테이지 맵 데이터 (텍스트 없음)
  BPLAY/FPLAY.COM         FM/SSG 음악 재생기
```

**텍스트 소스**: DISK_B.DAT 단일 파일. DISK_C.DAT·PLAY*.INF에는 번역 대상 없음.

## 핵심 발견: LZ 압축

**DISK_B.DAT는 LZ 압축** — 풍광전과 동일한 알고리즘.

```python
# compile_lz.decompress() 그대로 재사용 가능
dec = decompress(data, seek_pos)
```

GSC.COM 내 디스어셈블 확인 (0xf55):
- back-ref: `length = (al & 0x7f) + 3`, `offset = next_byte + 1`  
- literal: `length = al` (al < 0x80)
- 종료: `al == 0`

→ `compile_lz.py`의 `decompress()` 함수 동일 알고리즘, 그대로 적용.

## DISK_B.DAT 청크 테이블

```
파일 오프셋 0x000~0x3FF: 4-byte 엔트리 테이블
  [CX(2 LE), DX(2 LE)] → seek_pos = (CX<<16)|DX

엔트리 수: 65개
seek_pos=0 엔트리는 무시 (빈 슬롯)
```

코드 예시:
```python
seeks = []
for off in range(0, 0x400, 4):
    cx = struct.unpack_from('<H', data, off)[0]
    dx = struct.unpack_from('<H', data, off + 2)[0]
    seek = (cx << 16) | dx
    if seek and seek < len(data):
        seeks.append(seek)
seeks.sort()
# 압축 크기 = seeks[i+1] - seeks[i]
```

> ⚠️ 이전 NOTES에서 "8-byte 엔트리, type=0000 청크" 로 기록한 것은 **오류**. 실제로는 4-byte 엔트리.

## 스크립트 제어코드 (확정)

### 스킬/아이템 블록 (`62 00 XX XX ... 65`)

```
62 00 XX XX   블록 시작 (3바이트 인수)
[SJIS]        스킬/아이템 이름 (name)
64 XX         구분자 (1바이트 인수) → stat 영역 시작
[SJIS]        소비 스탯 (stat)
72 XX         줄바꿈 (1바이트 인수)
[SJIS]        설명 줄 (desc, 여러 줄 가능)
65            블록 종료
```

예시 (chunk 3):
```
62 00 0f 03  脳天砕
64 0c        消費ＳＰ１０
72 01        　こん身の力を込め　剣を
72 01        　敵の脳天めがけて振り下ろす
65
```

### 대화 블록 (`6e 00 67 XX ... 73 XX`)

```
6e 00   대화 섹션 시작 (1바이트 인수)
67 XX   화자 마커 (1바이트 인수)
[SJIS]  화자명  ※ 「로 시작하면 화자 없는 대사 (v4 수정)
72 XX   줄바꿈 (화자명과 대화 사이)
[SJIS]  대화 텍스트
72 XX   줄바꿈 (대화 줄 구분)
...
73 XX   대화 블록 종료 (1바이트 인수)
```

예시 (chunk 6):
```
6e 00  67 01  アリババ
72 01  「誰だ？
72 01  　入っていいぞ
73 30
```

화자 없는 케이스 (67 XX 직후 바로 대사):
```
6e 00  67 01  「ふっ　私もどうかしていますね   ← 화자 아님, 첫 대사줄
72 01  　彼女のことが
72 01  　こんなに気になるなんて…
73 30
```

### 이름/레이블 블록 (`64 XX [SJIS] 65`, XX ≠ 00)  ← v4 신규

```
64 XX   레이블 시작 (1바이트 인수, XX ≠ 00)
[SJIS]  이름 또는 레이블 텍스트
65      블록 종료
```

확인된 XX 값:
- `64 f6`: 캐릭터/적 이름 표시 (`アリババ`, `スマッシュ`, `手下` 등)
- `64 fc`, `64 01`: 상태 효과 레이블 (`毒`, `気絶` 등)
- `64 ff`, `64 fe`: UI 기호 (`→`)

예시 (chunk 0):
```
64 f6  アリババ  65
64 f6  スマッシュ  65
64 fc  毒  65
```

### 챕터 제목 (`64 00 XX XX [SJIS]`)

```
64 00 XX XX   챕터 제목 시작 (arg=00이면 추가 2바이트 읽음)
[SJIS]        챕터 번호 또는 제목 텍스트
72 01         줄바꿈 (선택)
73 30 65      블록 종료
```

예시 (chunk 6):
```
64 00 c5 28   第３章
72 01
64 00 5a 38   『アリババ　ついにつかまる！？』
73 30 65
```

### 기타 확인된 제어코드

| 바이트 | 역할 | 인수 |
|--------|------|------|
| `62 XX` | 텍스트 블록 시작 (일반) | 3바이트 |

## 파서 구조 (`kaitou_parser.py` v4)

### 알고리즘

1. **청크 테이블 파싱** → 65개 청크의 (seek, comp_size) 추출
2. **각 청크 LZ 해제** → `compile_lz.decompress(data, seek)`
3. **SJIS 밀도 계산** → 5% 미만 청크 스킵 (그래픽/코드 청크 제외)
4. **구조화 파서를 순서대로 실행** (각 파서는 소비 바이트를 `consumed` 셋에 기록):
   - `extract_skill_blocks(dec, chunk_idx, consumed)` — `62 00` 앵커
   - `extract_dialogue_blocks(dec, chunk_idx, consumed)` — `6e 00 67` 앵커
   - `extract_name_blocks(dec, chunk_idx, consumed)` — `64 XX` 앵커 (XX≠00, `65`로 종료)
   - `extract_title_labels(dec, chunk_idx, consumed)` — `64 00` 앵커
5. **SJIS 런 폴백** — `consumed` 구간 제외, 연속 2자 이상 런 추출
6. **중복 제거**: 동일 (chunk, offset) 쌍만 제거 (타입 우선순위: skill > dialog > title > label > unknown)
7. **노이즈 필터: 없음** — 분류는 번역 단계에서 수동으로

### 추출 결과 (v4)

| 타입 | 수 | 내용 |
|------|-----|------|
| `dialog` | ~763 | 대화 블록 (화자+대화줄) |
| `skill` | ~154 | 스킬/아이템 블록 (name+stat+desc) |
| `title` | ~115 | 챕터 제목·메뉴 |
| `label` | ~401 | 캐릭터명·레이블·상태효과 (64 XX 블록) |
| `unknown` | ~4604 | SJIS 런 (나레이션·UI·메뉴 포함, 일부 노이즈 포함) |

> 노이즈 필터 없음 — 분류는 번역자가 에디터에서 직접.
